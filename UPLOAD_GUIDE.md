# Manual upload guide

Everything in this archive is ready to go straight into a new GitHub
repository. Nothing needs renaming, moving or editing first.

---

## Option A: drag and drop through the browser

1. Create a new repository on GitHub. **Do not** tick "Add a README",
   "Add .gitignore" or "Choose a license". This archive already contains all
   three, and letting GitHub create its own produces a conflict you then have
   to resolve.
2. Unzip this archive.
3. On the empty repository page, click **uploading an existing file**.
4. Select everything **inside** the `cosmetic-finish-capability` folder, not
   the folder itself. Dragging the folder works too, but then every path gains
   an extra level and the relative image links in `README.md` break.
5. Commit.

**One caveat.** The browser uploader silently skips folders whose name begins
with a dot, so `.github/workflows/tests.yml` will not arrive this way. The
repository works fine without it; you simply do not get automated test runs on
push. To add it afterwards, use **Add file, Create new file**, type
`.github/workflows/tests.yml` as the filename, and paste the contents in. The
file is included in this archive for that purpose.

---

## Option B: push from the command line (recommended)

This preserves the commit history, which browser upload discards, and it
handles the dotfiles correctly.

The unzipped folder is already an initialised git repository with its history
intact. From inside it:

```bash
git remote add origin https://github.com/<your-username>/cosmetic-finish-capability.git
git branch -M main
git push -u origin main
```

If the archive you received has no `.git` folder, initialise one first:

```bash
git init
git add -A
git commit -m "Cosmetic finish process-capability simulator"
git branch -M main
git remote add origin https://github.com/<your-username>/cosmetic-finish-capability.git
git push -u origin main
```

### Deliberately not included

The Monte-Carlo sample dumps, `outputs/*_montecarlo.csv`, are roughly 2 MB of
raw simulation samples with no browsing value. They are regenerated by
`python scripts/run_study.py` and are excluded by `.gitignore`.

Also excluded: `__pycache__/`, `.pytest_cache/`, `.ruff_cache/`, and LaTeX
auxiliary files.

## Checking it worked

After uploading, confirm:

- [ ] Both figures render on the repository landing page. If they show as
      broken images, the upload gained an extra folder level; see step 4 above.
- [ ] `docs/report.pdf` opens in GitHub's PDF viewer.
- [ ] `CITATION.cff` produced a "Cite this repository" button in the sidebar.
- [ ] The licence shows as MIT in the sidebar.
- [ ] If you added the workflow file, the Actions tab shows a run.

To verify the code itself after cloning:

```bash
python -m pip install -e ".[all]"
python -m pytest
python scripts/run_study.py
```

All 62 tests should pass, and the study should reproduce the numbers quoted in
`README.md`.
